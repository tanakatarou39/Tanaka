# MikuMikuDance の操作パネルが GPU の面に隠れる不具合の修正 (Hangover の Android 表示ドライバー)

## 原因
主窓のクライアント領域から子窓を引いた見える領域は、MMD では 629〜898 個の矩形になります。これが `ADISP_MAX_CLIP_RECTS` (64) を超えると、`get_client_clip()` は `ADISP_CLIP_NONE` (切り抜きなし) を返していました。その結果、表示サーバーが GPU の面を操作パネルの上に丸ごと描いていました。

## 修正 (`mmd-clip-fix.diff`)
- **`ADISP_MAX_CLIP_RECTS` を 2048 に上げる。** 1 メッセージは 24 + 2048×16 バイト = 32 KiB で、`ADISP_MAX_MSG_SIZE` (128 KiB) に収まります。
- **上限を超えても「切り抜きなし」にしない。** 見える矩形のうち面積の大きいもの `max` 個だけを、帯の順 (y、x) のまま残します。捨てた小さな隙間には GPU を描かず、GDI の面が見えます。こうして、どう転んでも GPU の面が子窓の上に描かれないようにしています。
  - 試験の配置では、上限 512 のときに見える面積の 75〜100% が残りました。
  - 上限 2048 では、実機と同程度 (684 個、902 個) の配置はそのまま収まります。
- **結果の意味を分ける。** `ADISP_CLIP_NONE` は「何にも覆われていない」だけを表します。`0` は「全部覆われている」か「失敗した」ときです。失敗のときも、他の窓の上に描かない側に倒しています。上限超えのときは WARN を出したうえで、上の削減を行います。
- **縮尺の変換のあとで 1 画素未満になった矩形は捨てる。** 子窓と見える矩形の境目は同じ `scale()` で変換されるので、変換のあとも重なりません (単調な関数なら成り立ちます)。
- **重さ。**
  - 変化が無ければ送らない既存の比較 (`sent_clip`) はそのままです。
  - 毎フレームの処理は次の 3 つだけで、ソートは上限を超えたときにしか走りません。
    - `GetRegionData` で大きさを問い合わせる
    - 1 回 malloc する
    - 矩形を変換する
  - 32 KiB のメッセージを積むと、Wine の unix 側の小さなスタックでは苦しいので、メッセージの領域はヒープに取ります。
- **表示サーバー。**
  - `struct client_surf` の `clip` を固定長の配列から動的な配列 (`clip` / `clip_size`) に変えました。必要になったときだけ `realloc` で広げ、小さくはしません。
  - `realloc` に失敗したら `clip_count = 0` にして、描かない側に倒します。
  - 上限を超える要求や、短すぎるメッセージは、これまでどおり無視します。
- `render.c` の `draw_client_surfaces()` は変えていません (配列がポインターになっても同じ書き方で動きます)。

### 抜粋に無いため、diff に含めていない変更 (適用するときに必要)
1. **`struct client_surf` を確保する箇所:** 0 で埋めていなければ `surf->clip = NULL; surf->clip_size = 0;` を足す。
2. **`struct client_surf` を解放する箇所:** `free( surf->clip );` を足す。
3. **`struct android_client_surface` の `sent_clip[ADISP_MAX_CLIP_RECTS]`:** 何もしなくても 2048 個 (32 KiB) に広がります。気になる場合は、矩形の数とハッシュだけを持つ形にもできます。
4. **プロトコルの定義と `struct client_surf` の定義:** 実際のファイル名がわからないので、`app/jni/include/adisp_protocol_excerpt.h` と `app/jni/client_surf_excerpt.h` という仮の名前にしています。
5. **`scale()`:** 抜粋に無いため、試験では四捨五入 (MulDiv) と切り捨ての両方で確かめています。

diff は抜粋 (`orig/`) に対して作ったものなので、行番号は実際のファイルと合いません。`patch -p1` で文脈から当たるか、`new/` の関数をそのまま差し替えてください。

## 試験 (`test/`, `sh test/run.sh` で再現できます)
試験は、`new/` のコードを関数ごと**そのまま**抜き出して (`extract.py`) 組み込んでいます。

### `region_test` (mingw でビルドし、Wine 9.0 で実行)
- **何をするか:** Wine の GDI (`CreateRectRgn`、`CombineRgn(RGN_DIFF)`、`GetRegionData`) で、主窓に多数の子窓を置いた見える領域を求め、修正した `get_region_clip()` に通します。
- **配置:**
  - MMD のように操作パネルの部品を行に並べた配置。1280×720 で 684 個、1600×900 で 902 個の矩形になります。
  - 部品を散らした配置 (2430〜2507 個)
  - 2500 個の子窓 (10831 個)
  - 子窓なし
  - 全体を覆う子窓
  - 面の外にだけある子窓
  - 1 画素の隙間
  - 仮想座標の原点のずれ
- **上限:** 64、512、2048、矩形の数ちょうど、その 1 つ下、1
- **縮尺:** 等倍、0.5 倍、1.5 倍、1366×768、1000×333。それぞれ四捨五入と切り捨ての両方。
- **確かめること:**
  - 「切り抜きなし」になるのは、子窓が無いときだけ
  - 出した矩形が、縮尺を変換した子窓のどれとも重ならない
  - 矩形どうしが重ならない
  - 矩形が面の内側にある
  - 帯の順が保たれている
  - 上限以下のときは面積が一致し、等倍では GDI の領域と完全に一致する
  - 上限を超えたときは、捨てたどの矩形も残したどの矩形より大きくない
- 結果: `304282 checks, 0 failures`。元のコードでは、64 個を超えるすべての配置が `NONE (not clipped)` になります (`region_test.log`)。

### `server_test` (Linux でそのまま実行)
- **何をするか:**
  - 修正した `req_client_clip()` と、変更していない `draw_client_surfaces()` (GL の呼び出しなどはスタブ) に、`region_test` が出したクリップを通します。
  - 描いた四角形を調べます。トップレベルが面の右下を切る位置に置いています。
- **確かめること:**
  - 四角形が子窓に掛からない
  - 四角形が面とトップレベルの内側にある
  - 四角形どうしが重ならない
  - 描いた画素数が、クリップとトップレベルの積と一致する
  - 要求の境界: `ADISP_CLIP_NONE`、0、上限ちょうど、上限 + 1、短いメッセージ、知らない面 ID、配列を広げたあとに小さくする
- 結果: `176 cases, 91168 checks, 0 failures`。
- 元の振る舞い (64 個を超えたら切り抜きなし、`OLD_LIMIT=1`) では、95 件の配置で四角形が子窓に掛かり、失敗します。

## 確かめていないこと
- 実機と Hangover のリポジトリーでのビルド・動作 (どちらも使えないため)
- 矩形 2048 個を 1 個ずつ `draw_quad_uv` で描く重さ。MMD の 700〜900 個程度なら、これまで 4096 にした版で実機で動いていたとのことなので、同じ程度のはずです。重い場合は、描画をまとめる (1 回の draw call にする) 変更が次の候補です。
